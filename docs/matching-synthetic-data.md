# 모션 매칭용 가상 자료

이 자료는 이력서에 따라 연결되는 공고의 위치와 개수가 바뀌는지 확인하기 위한 교육용 합성 자료입니다. 실제 구인이나 실제 개인의 이력서를 수집한 자료가 아닙니다. 인물, 회사, 기간, 경력, 수치는 독립적으로 작성한 허구입니다.

## 구성

| 자료 | 새로 추가한 수 | 기존 자료 보존 | 저장 위치 |
| --- | ---: | --- | --- |
| AI 오케스트레이션 공고 | 30 | 기존 공고 30개 보존, 총 60개 | `job_postings` DB 테이블 |
| 여러 직무의 가상 이력서 | 200 | 기존 이력서 20개 보존, 총 220개 | `resume_examples` DB 테이블 |
| AI 오케스트레이션 업로드 이력서 | 10 | 위 200개와 별도 | 사용자가 지정한 바탕화면 폴더의 PDF와 TXT |

200개 이력서는 20개 직무군에서 각 10개씩 구성했습니다. 개발, 분석, 기획, 디자인, 상담, 물류, 회계, 매장, 조리, 안전, 교육 등의 직무를 포함합니다. 프로젝트 분야, 도구 조합, 근무 연수, 수행 범위, 작업 규모와 결과를 달리했습니다. 3종의 구성 순서를 사용했으며 이름만 바꾼 복제 문서가 아닙니다.

30개 공고는 모두 AI 오케스트레이션을 공통 요구사항으로 갖고 있습니다. 개별 공고는 문서검색, 상담, 제조, 매장, 교육, 보안, 금융, 물류 등 서로 다른 업무와 도구를 요구합니다. 기존 30개 공고는 여러 직무를 다루므로 AI 직무가 아닌 이력서도 기존 공고와 함께 비교할 수 있습니다.

10개 업로드 이력서는 RAG 문서검색, n8n 매장 자동화, 클라우드 실행환경, 콘텐츠 승인화면, Java 금융 서비스, 데이터 파이프라인, 센서 연결, OCR 증빙 검토, 고객상담, 신입 평가 실습으로 구분했습니다. 파일마다 수행한 일과 도구가 다르며 미경험 범위도 명시했습니다. PDF는 텍스트를 선택할 수 있으며 한글 글꼴을 포함합니다.

사이트 이름은 구조 참고 출처를 나타냅니다. 해당 서비스에서 내려받은 이력서 양식이나 공식 템플릿이라는 뜻이 아닙니다. 데이터의 `source_url`과 `source_urls`는 실제 가상 기업의 채용 링크가 아니라 형식 참고 링크입니다.

## 좌표

공고 JSON에는 `latitude`, `longitude`, `coordinate_precision`을 기록했습니다. 좌표는 국내 20개 도시의 대표 좌표를 사용한 시각화 예시이며 가상 회사의 실제 사업장 주소가 아닙니다. 같은 도시의 여러 공고는 겹칠 수 있습니다. 사용자 데이터의 정확한 위치가 필요하면 별도의 주소 확인과 좌표 저장 기능으로 대체해야 합니다.

## DB와 개인정보 경계

앱 초기화 시 `ResumeExampleRepository(database).seed(load_examples())`를 호출합니다. 테이블의 각 ID는 한 번만 추가되며 이미 있는 행은 덮어쓰지 않습니다. SQLite와 PostgreSQL에서 같은 어댑터를 사용합니다. 목록 API는 본문을 제외하고 개별 조회에서 본문을 읽습니다.

이 저장소에는 `source_type=synthetic` 자료만 들어갈 수 있습니다. 사용자가 올린 이력서는 원래의 계정별 workspace draft 경로를 사용하고 이 예시 저장소에 자동 수집되지 않습니다. 데스크톱 10개 이력서는 `load_examples()`에 포함되지 않습니다.

## 재생성

기본 JSON 생성에는 파이썬 표준 라이브러리만 필요합니다. 경로는 실제 폴더로 바꿔 실행합니다.

```powershell
python scripts/generate_matching_fixtures.py
python scripts/generate_matching_fixtures.py --desktop-dir '<업로드 예시를 저장할 폴더>'
```

PDF 생성에는 ReportLab과 한글 TTF 글꼴이 필요합니다. 생성 도구는 DB에 접속하지 않습니다.

```powershell
python scripts/export_matching_resume_pdfs.py --destination '<같은 업로드 예시 폴더>'
```

`matching_fixture_manifest.json`에 개수, 서로 다른 본문 수, 직무군 수, 원본 JSON의 SHA-256 해시를 기록합니다. 기존 `job_postings.json`과 `resumes.json`은 생성기가 수정하지 않습니다.

## 검증

`tests/unit/test_matching_fixtures.py`는 공고 30개 검증, 요구사항 추출, 국내 좌표 범위, 기존 20개와 새 200개 보존, 20개 직무군, 업로드 파서, DB의 재시작 및 반복 초기화, 업로드 자료의 예시 저장소 유입 차단을 확인합니다.

로컬 검증에서는 바탕화면의 실제 PDF 10개와 TXT 10개를 업로드 파서로 읽었습니다. PDF는 모두 1페이지이며 한글 텍스트가 추출되었습니다. Poppler로 10페이지를 이미지로 변환해 잘림, 겹침, 누락 글자가 없는지 확인했습니다.

점수는 이 서비스의 로컬 규칙을 사용한 문장 근거 충족도입니다. 이 자료의 가상 점수를 실제 합격 가능성이나 검증된 채용 판단으로 해석하지 않습니다.
