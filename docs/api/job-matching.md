# 이력서와 전체 공고 매칭

`GET /api/v1/job-matches`는 로그인 사용자의 저장된 이력서와 보완 답변을 현재 접근 가능한 공고와 비교해 `{job_matches: ...}`를 반환합니다. 공개 예시와 본인이 등록한 비공개 공고가 대상이며 다른 계정의 이력서·공고는 사용하지 않습니다. 요청에 다른 사용자 ID나 임의 점수를 전달하는 기능은 없습니다.

같은 결과는 `POST /api/v1/analysis`의 `report.job_matches`와 `GET /api/v1/workspace`의 `draft.report.job_matches`에도 포함됩니다. 이력서 변경·업로드는 이전 보고서와 보완 답변을 무효화합니다. 기존 보고서를 다시 읽을 때는 현재 공고로 매칭을 다시 계산해 공고 추가·수정·삭제를 반영합니다.

## 응답

| 필드 | 의미 |
| --- | --- |
| `threshold` | 연결 기준 60점, 경계값 포함 |
| `method` | `local_rules_v1` |
| `status` | `ready`, 이력서가 없는 `resume_required`, 공고가 없는 `no_jobs` |
| `total_jobs` | 현재 사용자가 볼 수 있는 전체 공고 수 |
| `evaluated_jobs` | 실제 점수를 계산한 공고 수 |
| `matched_count` | 평가 대상 중 60점 이상 공고 수 |
| `truncated` | 전체 공고가 1,000개를 넘어서 일부만 반환했는지 여부 |
| `items` | 점수와 무관하게 공고 ID 순서로 정렬한 표시 대상 |

각 항목은 `id`, `company`, `role`, `location`, `source_type`, `score`, `matched`, `status`, `evidence`를 포함합니다. `evidence`에는 요구사항 문장·근거 상태·연결 단어가 있으며 이력서 원문을 중복해서 포함하지 않습니다. `status`는 `scored`, `resume_required`, `no_requirements`입니다. 이력서가 없거나 공고에 평가 가능한 요구사항이 없으면 `score`는 `null`이고 연결하지 않습니다. 평가했지만 연결 근거가 없으면 점수는 0입니다.

공고가 1,000개를 초과하면 최신 등록 순서의 첫 1,000개를 평가하고 `truncated: true`로 알립니다. `total_jobs`는 전체 개수이고 `matched_count`는 반환한 평가 대상의 개수입니다. 현재 기본 카탈로그 600개는 모두 평가합니다. 유효한 좌표를 공급자가 제공하면 `latitude`·`longitude`를 반환할 수 있지만 현재 공고 저장소는 좌표를 저장하지 않으므로 위치 문자열을 사용합니다.

## 점수와 시각화

상세 모의지원 보고서와 같은 계산 함수를 사용합니다. 공고 요구사항 연결 70점, 수행 맥락 20점, 수치로 표현한 결과·규모 10점으로 합산합니다. 최대 12개의 중복되지 않는 요구사항을 비교하며, 같은 문구 반복이나 이름·날짜에 가산점을 주지 않습니다. 공고와 이력서에 나온 한국어·영어 동의어와 일반 단어를 비교하므로 특정 직무 분류에 제한하지 않습니다.

프론트엔드는 반환된 공고별로 흰색 점을 배치하고 `matched`가 참인 공고에만 중앙 이력서에서 선을 연결합니다. 모든 연결선은 같은 시작 시각과 진행률을 사용합니다. 공고 ID와 좌표를 유지하면 이력서가 바뀌어도 점 위치를 보존하면서 연결 대상과 개수만 갱신할 수 있습니다. 60점 이상 공고가 없으면 연결선 없이 표시합니다.

이 점수는 제출한 텍스트의 근거 충족도를 보여주는 로컬 규칙 점수입니다. 임베딩·의미 추론·경력 진위 검증을 하지 않으며 문맥이나 동의어를 놓칠 수 있습니다. 실제 합격 확률이나 회사의 채용 판단을 의미하지 않습니다. 전체 카탈로그 비교 과정은 외부 AI API를 호출하지 않습니다.

옆의 스테이터스 그래프는 보고서의 실제 `criteria`를 축으로 사용합니다. 각 축은 `score / max_score × 100`으로 표시하며 원래의 70·20·10점 배점과 총점은 바꾸지 않습니다. 현재는 3개 축이며 항목이 추가되면 해당 개수의 다각형으로 표시됩니다.

600개 조회에서 기술 목록은 최대 500개 ID씩 묶어 읽습니다. 공고 문장 파싱은 본문을 키로 하는 최대 1,024개 캐시에 보관합니다. 공고 본문을 수정하면 새로 파싱하며, 이력서 근거와 매칭 점수는 캐시하지 않고 요청마다 다시 계산합니다.

## 검증

`tests/unit/test_catalog_matching.py`, `tests/unit/test_catalog_fixtures.py`, `tests/integration/test_job_matching.py`가 59점과 60점 경계, 이력서 변경, 일반 직무, 점수 일치, 비공개 공고 격리, 빈 결과, 기존 보고서 갱신을 검증합니다. 모든 API 테스트는 임시 SQLite DB를 사용합니다.
