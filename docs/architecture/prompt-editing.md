# 프롬프트와 검색 안내 수정

기존 API 응답과 규칙 기반 점수는 유지하고, LangGraph가 검색 → 규칙 분석 → 선택적 코칭 → 검증 → 최대 1회 재시도 → 대체 결과 순서를 조정합니다.

## 프롬프트 파일

- `app/agent/prompts/coaching.md`: 코칭 지시문. 한국어로 수정할 수 있고 다음 분석부터 다시 읽습니다.
- `app/agent/prompts/registry.json`: 템플릿 목록, 기본 ID, 버전, 켜기/끄기, 검색 개수, 재시도 한도.
- 새 템플릿을 같은 폴더에 `.md`로 추가한 뒤 `prompts`에 ID/파일명/버전을 등록하고 `default` 또는 `.env`의 `CAREERLENS_COACH_PROMPT`에서 선택합니다.
- 삭제하려면 선택을 다른 ID로 변경한 뒤 등록과 파일을 지웁니다. 활성 파일을 잘못 삭제하거나 경로가 잘못되면 코칭을 중단하고 기존 규칙 결과를 유지합니다.
- 문구 변경은 파일로 가능하지만 새 도구·새 분석 단계·출력 필드는 스키마 및 그래프 연결 코드 수정이 필요합니다.

## 기본 실행과 선택적 AI

기본 `.env`의 `CAREERLENS_ANALYSIS_MODE=rules`는 외부 모델을 호출하지 않습니다. 프롬프트 문구는 이 모드의 점수나 기존 설명을 변경하지 않습니다.

실제 모델을 사용하려면 `CAREERLENS_ANALYSIS_MODE=llm`, `CAREERLENS_LLM_MODEL`, `OPENAI_API_KEY`를 본인의 백엔드 `.env`에 설정합니다. 그때만 길이를 제한한 이력서·공고·답변 발췌와 내부 작성 안내를 OpenAI에 보냅니다. 이력서의 이름·연락처 자동 마스킹은 아직 없으므로 실제 자료 사용 전 데이터 처리 방침을 확정해야 합니다. 원격 LangSmith 추적은 코드에서 비활성화합니다.

현재 연결은 OpenAI 어댑터 하나입니다. 다른 제공자는 `app/integrations/llm`에 어댑터를 추가하고 같은 구조화 출력 계약을 맞춰야 합니다. 키만 바꿔 임의의 제공자와 호환된다고 가정하지 않습니다.

## 출력 검증과 한계

Pydantic이 필드·길이·추가 필드를 검사하고, 인용은 모델에 실제 전달한 이력서·보완 답변의 발췌에 존재해야 합니다. 참고 ID도 검색된 문서에 있어야 합니다. 실패하면 오류 코드만 다시 전달해 한 번 수정 요청하고, 계속 실패하면 기존 보고서를 반환합니다. 모델이 점수를 바꾸는 필드는 허용하지 않습니다. 이 검증은 인용의 존재와 형식을 확인하며 문장 전체의 의미적 진실성을 보장하지 않습니다.

참고 안내는 `data/knowledge/policies/career-guidance.json`에서 추가·삭제·수정합니다. 현재 검색은 로컬 키워드 기반이며 벡터 검색, 임베딩, 하이브리드 검색·리랭킹은 아직 연결하지 않았습니다. 검색 안내는 지원자의 경험 근거가 아니며 화면에 별도로 표시합니다.

컨텍스트는 길이를 제한해 발췌합니다. 의미 요약, 장기 기억, 체크포인터는 아직 없습니다. 결과에 포함한 단계 목록은 실행한 작업의 기록이며 모델의 내부 사고 과정이 아닙니다.

## 검증

`python -m unittest tests.unit.test_agent_workflow -v`는 가짜 응답으로 인용 조작·없는 출처·잘못된 스키마·공급자 실패·프롬프트 경로 이탈을 검증합니다.

`python scripts/evaluate-agent.py`는 고정된 가상 오류 5개를 비교하고 `evaluations/results/agent-baseline-v1.json`을 만듭니다. 실제 LLM 성능·채용 적합도·운영 환경의 성공률을 뜻하지 않습니다.
