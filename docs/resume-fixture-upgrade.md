# 가상 이력서 확장본

`career-resumes-v2`는 기존 이력서의 ID를 유지하면서 본문과 자기소개를 보강한 자료입니다. DB 예시 220개와 별도 업로드 예시 40개를 포함합니다. 인물, 기관, 경력과 수치는 모두 허구이며 실제 지원자의 이력서를 수집한 자료가 아닙니다.

## 내용

- 기존 `resume-01`부터 `resume-20`까지와 `synthetic-resume-001`부터 `synthetic-resume-200`까지의 ID를 유지합니다.
- 업로드 예시의 `desktop-ai-01`부터 `desktop-ai-10`까지도 유지하고 `desktop-ai-40`까지 추가했습니다.
- 01~30은 AI 오케스트레이션 개발, 평가, 기획과 운영에 관련된 사례입니다. 31~40은 백엔드, 프론트엔드, 디자인, 기획, 마케팅, 상담, 물류, 회계, 조리, 교육 등 다른 직무입니다.
- 각 본문은 약 2,600~3,300자로 자기소개와 지원동기, 담당 범위, 두 가지 프로젝트의 상황·행동·결과, 강점, 개선할 점, 기술 사용 범위, 교육과 기여 계획을 담았습니다.
- 역할별로 문제와 판단 과정이 다릅니다. 같은 직무의 10개 사례도 경험한 상황, 첫 소개와 강점 사례가 서로 다릅니다.
- 경력 연수는 기존 본문에 적힌 연수를 우선 사용합니다. 긴 경력자의 AI 프로젝트는 2025년 이후의 전환 사례로 구분했습니다. 신입과 보조 역할은 상용 서비스 전체를 운영한 사람으로 서술하지 않습니다.

형식의 참고 출처는 기존 [자료 출처 문서](matching-synthetic-data.md)에 기록된 사람인, 알바몬과 당근의 공개 안내입니다. 이번 확장에서는 지원자 프로필이나 실존 인물의 경력을 수집하지 않았습니다.

## 파일과 재생성

`scripts/enrich_resume_fixtures.py`는 이력서 파일만 갱신하며 공고 파일이나 데이터베이스에 쓰지 않습니다. `scripts/resume_narrative_catalog.py`에 직무별 서술과 기술별 사용 범위를 정리했습니다. 기존 20개 이력서의 원래 본문은 `data/examples/resume_original_sources.json`에 보관해 반복 실행 때 문단이 중복되지 않게 했습니다.

```powershell
python scripts/enrich_resume_fixtures.py --desktop-dir '<새 이력서 폴더>'
python scripts/export_matching_resume_pdfs.py --destination '<같은 폴더>'
```

PDF 내보내기는 ReportLab과 한글 TTF 글꼴을 사용합니다. 이번 출력은 바탕화면 `CareerLens-가상이력서-40개` 폴더에 저장했으며 PDF 40개와 같은 내용의 UTF-8 TXT 40개입니다. 기존 `CareerLens-AI오케스트레이션-가상이력서-10개` 폴더는 수정하지 않았습니다.

`resume_enrichment_manifest.json`에 버전, 개수, 본문 길이, 고유 본문 수와 이력서 JSON의 SHA-256 해시를 기록합니다. 이전 `matching_fixture_manifest.json`은 첫 버전 생성 시점의 기록입니다. 이후 자료는 이 문서와 이력서 확장 manifest를 기준으로 확인합니다.

## 저장소 갱신

일반 `seed()`는 계속 누락된 ID만 추가합니다. 앱이 `refresh_packaged(load_examples())`를 호출하면 알려진 기본 220개 ID와 `fixture_pack=career-resumes-v2`, `fixture_version=2`, `source_type=synthetic`가 모두 맞는 항목만 갱신합니다. 같은 내용을 다시 실행하면 변경 수는 0입니다.

이 경로는 계정별 workspace 업로드 이력서를 읽지 않습니다. 다른 ID로 저장된 가상 예시도 그대로 두며, 알 수 없는 ID를 갱신 대상으로 전달하면 오류를 반환합니다. 기존 ID의 갱신은 사용자가 요청한 기본 예시 내용 보강을 반영하기 위한 동작입니다.

목록 응답에서는 `resume_text`와 `resume_sections`를 제외합니다. 상세 조회에서만 전체 본문과 문서 구성 정보를 가져오므로 목록을 여는 것만으로 220개 본문을 전송하지 않습니다.

## 검증

- DB 기본 220개와 업로드 40개는 각각의 기존 ID를 보존합니다.
- 260개 전체 본문은 고유하며 최소 2,200자를 넘습니다.
- 같은 직무의 소개와 강점 문단이 모두 동일하지 않은지 확인합니다.
- DB에 짧은 이전 예시가 있을 때 새 버전으로 갱신되며, 반복 갱신과 무관한 행의 보존을 확인합니다.
- 40개 이력서의 연결 결과가 여러 집합과 개수로 나뉘며 모든 공고에 자동 연결되지 않는지 확인합니다.
- PDF 40개는 모두 2페이지이며 한글 글꼴을 포함합니다. PDF와 TXT 80개를 실제 업로드 파서로 읽어 모든 원문 문단이 남는지 확인했습니다.
- 최종 PDF 80페이지를 Poppler로 렌더링하고 대표 페이지 원본과 전체 페이지 모음을 검토했습니다.
